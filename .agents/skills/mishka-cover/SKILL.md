# mishka-cover — Концептуальная обложка поста в стиле «Мишка на сервере»

Этот скилл — координатор пайплайна «статья → концепт → брендовый SVG». Твоя задача: взять статью, понять её центральную идею, придумать визуальную метафору и нарисовать чистую векторную обложку по дизайн-коду блога. Композицию, цвета и подписи ты придумываешь сам — это и есть суть работы. На выходе — `cover.svg` в page bundle поста, растровый сосед `cover.png` под og:image и правка `cover:` во frontmatter (шаг 4).

Этот скилл — про **эссе и «как устроено»-разборы**: концептуальные обложки без маскота. Для howto с весёлым медведем — это другой инструмент (см. §5 BRANDING.md), здесь маскота нет. По дизайн-коду v0.2 теплоту бренда несут голос, маскот и howto-обложки; концепт-обложка эссе живёт в холодной системе — и это на бренде, а не отступление от него.

Перед началом, если в рабочем каталоге есть `BRANDING.md` — прочитай его: бренд-токены могли поменяться. Значения ниже — снимок дизайн-кода v0.2 (холодная палитра catppuccin, акцент Sapphire); если файл свежее, он главнее.

## Шаг 1. Прочитай и пойми статью

Если дан URL — выфетчи и прочитай. Если markdown-файл — прочитай целиком. Определи:

- **Заголовок** — как звучит в посте (для верхней строки обложки).
- **Подзаголовок / тезис** — одна фраза, которую пост доказывает (meta-description часто уже её содержит). Это вторая строка обложки.
- **Центральная метафора** — то единственное, что обложка должна показать. Не пересказ статьи, а её ядро. Примеры: «надёжность = диалог двух сторон», «burn-rate = скорость утечки денег», «SLO = чертёж». Если метафор несколько — выбери одну, самую несущую.
- **Канал/подпись** — по умолчанию `Мишка на сервере · @jtprogru_channel`.

**Критерий хорошей метафоры**: её можно нарисовать схемой из 3–5 объектов так, что смысл читается без чтения статьи. Если для понимания нужен абзац текста — метафора не та.

## Шаг 2. Спроектируй концепт обложки

Опиши пользователю словами, что будет на обложке, **до** рисования:

```txt
🎨 Концепт обложки
   Метафора: ...
   Композиция: что слева / в центре / справа, что их связывает
   Где горит акцент (сапфир): ровно на смысловом центре статьи
   Текст на картинке: заголовок + тезис + подпись
```

Принципы композиции (из §0 BRANDING.md — «холодный инженерный цвет + тёплая подача через голос и маскота»):

- **Холодная база, один холодный акцент.** Структурные/нейтральные элементы — catppuccin surface-шкала и приглушённый серо-синий. Сапфир (`#7dc4e4`) светится **только** на смысловом центре — там, где у статьи кульминация. Не больше одного смыслового очага акцента.
- **Много воздуха.** Не заполняй холст под завязку. Сетка-фон тихая, элементы дышат.
- **Симметрия только когда она смысловая** (например, две равноправные стороны диалога).
- **Без маскота** — это эссе/концепт-обложка (§5). Теплота бренда в этой обложке не через цвет, а через выбор метафоры и голос заголовка.

Жди реакции пользователя на концепт, прежде чем рисовать. Если он сразу просит «рисуй» — рисуй.

## Шаг 3. Нарисуй SVG по бренд-токенам

Рисуй на canvas **1050×480** — это **зафиксированный широкий формат** обложек блога (соотношение ~2.19:1). Не меняй его без явной просьбы пользователя. Остальные значения ниже — **дефолты**: если пользователь просит другой акцент — переопредели, но формат и бренд-каркас по умолчанию держи.

### Цвет (§2 BRANDING.md) — дефолты, тёмная тема (catppuccin Macchiato)

Обложки рендерятся на тёмной базе, поэтому берём Macchiato-ступени.

| Роль | HEX | Где |
| ------ | ----- | ----- |
| Фон (верх градиента) | `#24273a` | catppuccin Macchiato base, `theme-color` блога (`--bg`) |
| Фон (низ градиента) | `#1e2030` | mantle, мягкий вертикальный градиент (`--bg-elev`) |
| Поверхности / карточки | `#363a4f` | боксы, подложки — surface0, приподнят над base |
| Бренд-акцент (декор) | `#7dc4e4` | **только смысловой центр**: заливки, бордеры, очаг (Sapphire, `--accent-400`) |
| Акцент-текст (тёмная тема) | `#7dc4e4` | акцентные подписи, ~7.5:1 на base, AAA (Sapphire, `--accent-300`) |
| Тёмный край акцента | `#0b7285` | глубина сапфирового очага, тёмное основание свечения (`--accent-700`) |
| Основной текст | `#cad3f5` | заголовок, метки боксов (`--fg` dark, catppuccin text) |
| Приглушённый текст | `#a5adcb` | тезис, мета, нейтральные стороны (`--fg-muted` dark, subtext0) |
| Границы / сетка | `#494d64` | разделители, тихая сетка-фон (surface1) |

> **Про surface-ступени.** В BRANDING.md `--border` = surface0 (`#363a4f`), а `--bg-elev` = mantle. На обложке боксы должны читаться приподнятыми над фоном, поэтому карточки — surface0 (`#363a4f`), а их рамки и сетка — на ступень светлее, surface1 (`#494d64`). Это ближайшая «приподнятая» пара из той же катпуччиновской шкалы, а не второй бренд.

**Один акцент — Sapphire.** Никаких вторых ярких брендов: ни тёплого янтаря/оранжа (это старый акцент v0.1, `#fb923c` больше не используется), ни зелёного, фиолетового, розового. Если нужно различать сущности — различай нейтральными оттенками catppuccin surface-шкалы и формой, а не вторым ярким цветом. Семантические цвета callouts (§2) на обложках не используются.

### Типографика (§3 BRANDING.md) — дефолты

- **Заголовок и проза** — humanist sans: `font-family="'PT Sans', sans-serif"`. Заголовок ~25px `font-weight="700"`, тезис ~13px `#a5adcb`.
- **Технические метки** (`SRE`, `SLO`, `error budget`, имена сущностей) — `'JetBrains Mono', monospace`. Mono — только на коротких тех-акцентах, **не** на прозе (§3: mono в прозе «кричит лог-файл»).
- **Подпись канала** — mono, `#7dc4e4`, ~11px.
- Регистр естественный, без КАПСА (кроме коротких тех-аббревиатур вроде `SRE`).

### Геометрия и чистота

- **Внешний фон — прямые края, без `rx`.** `<rect x="0" y="0" width="1050" height="480">` заливает весь холст. **Никакого скругления внешнего фона** — скруглённый угол на тёмном фоне даёт полупрозрачную кромку, которая читается как гало. Скругление (`rx="8..12"`) разрешено только у внутренних боксов.
- **Никаких фильтров.** Запрещены `<filter>`, `feGaussianBlur`, `feDropShadow`, любые `blur()`/тени. Глубину делай слоями непрозрачных фигур и градиентами заливки, не размытием.
- **Градиенты** — допустимы (`<linearGradient>`) для фона, свечения сапфирового очага, зон глубины. Это не противоречит чистоте: гало даёт именно размытие/тень и альфа-кромка, а не градиент-заливка.
- **Текст по вертикали** в боксах — `dominant-baseline="central"` + `y` в центре бокса.
- **Контраст ≥ AA** (§8): любой текст читаем на своей подложке. Тезис `#a5adcb` на base — проверяй, что не проваливается; заголовок всегда `#cad3f5`.
- **Safe area по бокам.** На самой странице поста обложка показывается целиком, но в карточках листингов тема кропает её под 16:10 (`.post-card__cover-wrap`), срезая примерно по 13% ширины с каждой стороны. Всё, что должно уцелеть в миниатюре, держи в центральных ~75% холста, то есть между `x≈130` и `x≈920`. Подпись канала и заголовок отцентрованы и переживают кроп сами; страдают именно метки у левого и правого краёв.
- **Низ холста трогай осторожно.** Подпись канала стоит примерно в 17px от нижнего края — это исторически совпало с точкой, где тема резала обложку по высоте. Сейчас тема широкие обложки не кропает (класс `post-cover--wide`), но запас в 15–20px до края держи, чтобы не зависеть от чужого CSS.

### Референс-шаблон

Скелет ниже — отправная точка структуры; заменяй метафору, держи бренд-каркас (одна метафора: «две стороны + светящийся сапфировый очаг в центре»):

<!-- база: прямые края, весь холст, без rx -->

<!-- тихая структурная сетка -->

<!-- СМЫСЛОВОЙ ЦЕНТР: единственный сапфировый очаг (#7dc4e4) -->

## Шаг 4. Положи в репозиторий и растеризуй

Обложка — не отдельный файл «куда-нибудь», а часть page bundle поста. В репозитории `jtprog.ru` конвенция такая:

```txt
content/posts/<slug>/
├── index.md
├── cover.svg   ← вектор, рисуешь ты; отдаётся на самой странице
└── cover.png   ← растр 2100px, генерируется скриптом; уходит в og:image
```

Имя всегда `cover.svg`, не `<slug>.svg` — партиал темы ищет ресурс в бандле поста. Каталог `assets/covers/` для концепт-обложек **не** используется: там лежат общие категорийные заглушки (`opinions.png`, `devops.png` и подобные), которые концепт-обложка как раз заменяет.

**Растр обязателен.** SVG нельзя отдавать в `og:image`: ни Telegram, ни VK, ни Facebook, ни Twitter его не рендерят — пост шарится без превью, хотя карточка резервирует под картинку место. Партиал `cover_og_image.html` ищет растрового соседа с тем же именем и отдаёт в OG именно его.

```bash
make cover-rasterize   # обходит content/posts/*/cover.svg и assets/covers/*.svg
```

Скрипт идемпотентный: пропускает файл, если PNG новее SVG, и — внимание — **никогда не понижает разрешение уже существующего PNG**. Если ты правишь SVG после первой растеризации, PNG шириной 2100px он молча пропустит с сообщением «существующий PNG шире». Тогда перерисовывай напрямую:

```bash
rsvg-convert --width=2100 --keep-aspect-ratio --format=png \
  --output=content/posts/<slug>/cover.png content/posts/<slug>/cover.svg
```

**Frontmatter поста** приводи к тому же виду, что у остальных концепт-обложек:

```yaml
cover:
  image: cover.png
  alt: 'что изображено на схеме, одной фразой'
  caption: 'Создал «Мишка на сервере» · AI-assisted'
  relative: false
```

В `image` идёт **растр**, не вектор. Тема сама подхватит его и для страницы, и для соцсетей, а Hugo сгенерирует webp-варианты и srcset. `alt` описывает содержимое схемы, а не категорию поста.

**Проверка «нет гало».** В системе нет `cairosvg` и `PIL`, зато есть `rsvg-convert` (librsvg). Отрисуй на непрозрачном фоне и просто посмотри результат — гало видно глазом по светлой кромке вдоль края:

```bash
rsvg-convert --width=1050 --keep-aspect-ratio --format=png \
  --background-color='#24273a' --output=/tmp/_check.png content/posts/<slug>/cover.svg
```

Заодно это лучший способ вычитать саму обложку: перекрытия подписей, стрелки в пустоту, слипшиеся элементы на глаз ловятся мгновенно, а в исходнике SVG — нет.

## Шаг 5. Отдай результат

Отдай `.svg` пользователю на просмотр. Краткий отчёт:

```md
✅ Обложка готова: content/posts/<slug>/cover.svg (+ cover.png 2100px)

🎨 Метафора: ... (одна фраза)
💠 Сапфир светится на: ... (смысловой центр)
🅰 Бренд: один сапфировый акцент #7dc4e4 на catppuccin-базе, PT Sans + JetBrains Mono, без гало

⚠️ Что проверить:
- Заголовок на картинке = заголовок поста? (если сократил — скажи)
- Тезис помещается в одну строку на 1050px? (если длинный — предложи перенос/сокращение)
```

Скажи явно, что тронул `index.md` — заменил категорийную обложку на свою. `lastmod` при этом **не** двигай: смена обложки не правка текста. Если хочется, чтобы поисковики перечитали страницу, спроси отдельно.

Если уместно — предложи опции: версия без текста заголовка (чтобы не дублировать `<title>` поста), конвертация в AVIF/WebP.

## Правила, которые нельзя нарушать

- **Только один холодный акцент — Sapphire.** `#7dc4e4` (`--accent-300/400`) и его тёмный край `#0b7285` (`--accent-700`). Никаких вторых ярких брендов: ни тёплого янтаря/оранжа (старый акцент v0.1 `#fb923c` больше не используется), ни зелёного, фиолетового, розового. Различай сущности нейтральной catppuccin surface-шкалой и формой. Это ядро дизайн-кода (§2).
- **Внешний фон без скругления и без фильтров.** Прямые края на весь холст; ноль `<filter>`/`blur`/тени. Иначе по краю появляется гало.
- **Mono — только тех-метки, проза — humanist sans.** Не верстай весь текст моноширинным (§3).
- **Без маскота.** Это концептуальная обложка эссе (§5). Медведь сюда не ставится.
- **Не выдумывай заголовок.** Бери из статьи. Если сокращаешь ради ширины — скажи пользователю.
- **Никогда не оставляй обложку без растра.** `cover.svg` без `cover.png` рядом = пост шарится без превью во всех соцсетях. И во frontmatter идёт именно `cover.png`.
- **Контраст ≥ AA.** Любая текстовая пара проверяема; не клади приглушённый текст на тёмное так, что он пропадает (§8). Катпуччиновские тона спроектированы под подсветку синтаксиса, а не под body-текст — проверяй пары, а не доверяй по умолчанию.
- **BRANDING.md главнее этого снимка.** Если в каталоге есть свежий `BRANDING.md` — токены бери из него; значения здесь — дефолт на случай его отсутствия.
- **Дефолты переопределяемы.** Если пользователь явно просит другой акцент, формат или добавить маскота — выполняй, но по умолчанию держи бренд-каркас.
